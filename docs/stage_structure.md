# 실험 진행 구조 (사용자 결정 2026-10-14, 원본은 Notion 「실험 진행 구조 결정: 단계별 통제 실험 A→B→C→D와 되돌아가기」)

목표: 맥락을 어떻게 쓰면 원본 캡션을 넘을 수 있는가(복원 성능 향상). 맥락 라벨이 의미가 있는지 보는 검증(사물 너머 고유 기여)은 별개로 끝났고 이번 실험에서 다시 하지 않는다.

원칙: 각 단계에서 환경을 철저히 고정하고, 다음 단계에서는 변인 하나만 바꾼다. 단계는 서로 의존적이고 의존 방식을 모르므로 어느 단계로든 되돌아가서 다시 하는 것이 정당하다(바꾼 변인과 고정한 환경은 항상 기록).

- A 텍스트를 다루는 방식 (전체 복셀, 같은 ridge decoding, 전처리 a, CLIP 고정): 거의 끝남
- B 복셀 압축·축 찾기 방법 (RRR, DDR, PCA, CCA; A에서 정한 텍스트 방식 고정): 아직
- C 맥락 차원별·ROI별 처리 (B에서 정한 압축 환경 고정): E4를 압축 없는 환경에서 먼저 해 봄, B 이후 다시
- D 파이프라인 구조 (병목 encoder–decoder, MIRAGE+맥락 등): 마지막

보류: E5(`docs/roi_matched_criteria.md`)는 C 단계에서 다시 설계. E3(잡음 제거)는 결론에 쓰지 않는 부가 탐색.
