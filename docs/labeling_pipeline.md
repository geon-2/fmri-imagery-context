# Context 라벨링 파이프라인

이 문서는 이미지마다 붙이는 맥락 라벨을 어떻게 만들었는지, 어떤 시행착오를 거쳤는지, 지금 어떤 상태인지를 정리한다.
논의와 결정의 원본은 Notion 연구 노트("라벨링 구조 결정")에 있고, 여기에는 코드를 읽을 때 필요한 만큼만 옮겼다.

## 전체 흐름: 프롬프트를 다듬은 뒤 넓혔다

라벨링은 작은 규모에서 프롬프트와 항목 구조를 먼저 다듬고, 안정된 뒤에 규모를 넓히는 순서로 진행했다.

| 단계 | 규모 | 한 일 | 얻은 것 |
|---|---|---|---|
| 1. 파일럿 | 300장 | Claude로 라벨링과 누수 판정을 끝까지 돌려 봄 | 캡션 기반은 사물 위주라 맥락이 빠짐 → 이미지를 직접 보는 방식(v3)으로 전환. 누수가 높게 나와 삭제 기준이 아닌 표시로 둠 |
| 2. 직접 라벨링 | 200장 | 파일럿 이미지를 사람이 보고 직접 라벨링 | 사람은 직전·의도·다음 사건까지 떠올린다는 점 → implied_event 추가(v4), 공간 규모·구도 항목 확인 |
| 3. 프롬프트 다듬기 | 코어 1,000장 | 파일럿을 코어 1,000장으로 넓히며 프롬프트 수정(v7~v9) | 문장 복사, 이미지를 보지 않고 끝내는 문제, 영어 규칙 → 복사 금지(v8), 영어(v9), 자동 검사 추가 |
| 4. 규모 확대 | 11,150장 | 단위별 새 세션 + 자동 검사로 진행 | 라벨 수 부족을 최소 개수(v10)로 보완 |

사람 라벨 200장은 2단계에서 라벨에 필요한 요소를 확인하고 프롬프트를 다듬는 데 쓴 자료다. 같은 자료로 프롬프트를 다듬었으므로 자동 라벨의 정확도를 재는 검증 기준으로는 쓰지 않는다. 검증은 11,150장 중 일부를 직접 확인하는 방식으로 한다.

## 무엇을 만드는가

NSD 이미지 한 장마다 장면의 맥락을 6개 항목으로 적는다. 항목마다 값이 여러 개 있어도 된다.

| 항목 | 담는 내용 | 최소 개수 |
|---|---|---|
| place_type | 어떤 장소인가 | 2 |
| environment | 실내/실외, 조명, 날씨, 붐비는 정도 등 | 3 |
| activity | 지금 화면에 보이는 동작, 또는 그 공간이 쓰이는 방식 | 2 |
| implied_event | 화면 밖 이야기: 직전에 있었을 일, 지금 행동의 의도, 다음에 일어날 일 (근거가 있을 때만) | - |
| scale | 공간의 크기와 구도 | - |
| notes | 위 항목에 안 들어가는 보충 내용 (대부분 비어 있어야 함) | - |

## 원칙

- 라벨을 붙이는 단계에서는 해석을 하나로 정하지 않는다. 표현이 달라도 억지로 합치지 않고, 같은 이미지를 독립적으로 여러 번 라벨링해서 값마다 나온 비율을 남긴다.
- 사물 이름과 관계 표현(on, next to 등)은 라벨로 쓰지 않는다. 다만 맥락은 사물과 이어져 있어서 완전히 떼어 낼 수는 없다. 라벨이 사물을 알려 주는 정도(누수)는 삭제 기준이 아니라 나중에 분석에서 고를 수 있는 표시다.
- 라벨은 영어로 쓴다(이후 문장 embedding에서 언어가 섞이지 않게).
- 이미지가 1차 근거다. COCO 캡션은 참고만 하고, 캡션에 없어도 이미지에서 보이면 라벨로 쓴다.

## 지금 방식

```
scale_queue.py      이미지 순서를 시드로 고정 (코어 1,000장 + 나머지 시드 셔플), 50장 단위로 나눔
download_pool.py    COCO 서버에서 이미지 내려받기
run_scale.py        단위마다 새 `codex exec` 세션을 열어 라벨링 → validate_unit.py로 검사 → 통과분만 저장
```

- **단위마다 새 세션.** 앞 단위의 출력이 다음 단위에 섞이지 않게 하려는 것이다. 처음에는 배치 50개를 한 세션에서 이어서 돌렸는데, 앞 이미지의 문장이 무관한 이미지에 복사되는 일이 있었다.
- **자동 검사.** 라벨링이 끝나면 추가 LLM 호출 없이 산출물과 작업 세션 로그로 이미지마다 검사한다.

| 검사 | 확인하는 것 | 걸리면 |
|---|---|---|
| 이미지 열람 | 작업 로그에 그 이미지를 열어 본 기록이 있는지 | 그 이미지만 다시 |
| 형식 | 6개 항목이 모두 있고 값의 형태가 맞는지 | 그 이미지만 다시 |
| 문장 복사 | 같은 문장이 관련 없는 이미지에 붙어 있는지 | 그 이미지만 다시 |
| 캡션 바꿔쓰기 | 캡션 단어만 재배열한 것은 아닌지 | 그 이미지만 다시 |
| 언어 | 라벨이 영어인지 | 그 이미지만 다시 |
| 최소 개수 | 항목별 최소 개수(place_type 2, environment 3, activity 2)를 채웠는지 | 그 이미지만 다시. 마지막(세 번째) 시도에서는 못 채워도 표시만 하고 받아들임(채우려고 지어내는 것을 막고, 라벨 없이 남는 이미지가 없게 함) |
| 반복 문장, 처리 시간 | 여러 이미지에서 반복되는 문장, 처리가 지나치게 빨랐는지 | 표시만 하고 유지. 같은 상황이 반복되면 같은 문장이 나오는 게 정상이라 다시 하지 않음(실제로 v10에서 가장 많이 반복된 문장이 8장) |

- **저장.** 통과한 이미지는 바로 `accepted/`에 저장하고, 실패한 이미지만 다시 시도한다(최대 3회). 반려된 원본은 지우지 않고 `quarantine/`에 둔다. 시도마다 모델, effort, 프롬프트 해시, 토큰, 소요 시간을 `ledger.jsonl`에 기록하므로 어느 버전으로 만든 결과인지 재구성할 수 있다.
- **모델.** GPT-5.5(effort medium). 5장 시험에서 Claude, GPT-5.5, GPT-5.6 계열의 품질 차이가 작았고, 대량 처리는 사용량 면에서 Codex가 유리해서 정했다.

## 프롬프트 버전

프롬프트는 `.claude/agents/context-classify.md`에 있고, 파일 안 `prompt_version` 주석이 버전이다. 고칠 때는 버전을 올린다.

| 버전 | 바뀐 점 | 계기 |
|---|---|---|
| v1~v2 | 다중 라벨과 독립 샘플, 이미지 배치 처리 | 초기 설계, 호출당 고정비 절감 |
| v3 | 이미지를 직접 보고 라벨링 | 캡션이 사물 위주라 맥락이 빠짐 |
| v4 | implied_event 추가 (5항목) | 직접 라벨링해 보니 사람은 직전과 다음까지 떠올림 |
| v7 | implied_event를 세 갈래로, notes 추가, 최대한 뽑기 | 이미지에 없는 세부를 지어내고 하나로 단정하는 경향 |
| v8 | 다른 이미지의 문장 복사 금지 | 문장 복사 발견 |
| v9 | 라벨을 영어로 | 첫 시험에서 한국어로 나옴 |
| v10 | 항목별 최소 개수 명시 | 처리하는 이미지 수가 많을수록 이미지당 라벨이 줄어듦 |

## 결과

2026-10-01 기준 11,150장(코어 1,000장은 v9, 그 밖은 v10)에서 라벨링을 멈췄다. Codex 주간 사용량을 절반 정도만 쓰기로 해서, 새 이미지는 약 1,150장까지만 진행했다.

| 항목 | 값 |
|---|---|
| 처음 검사에서 통과한 비율 | 1만 장 시점 99.99% (10,061장 중 재작업 1장). 이후 구간은 9월 30일 밤 출력 없이 끝난 단위 9개(네트워크·절전 추정)가 섞여 있어 별도 집계하지 않음 |
| 이미지당 라벨 | v10 평균 10.2개 (v9는 7.8개), v10 10,250장 기준 |
| 항목별 평균 (v10) | place_type 2.02, environment 3.39, activity 2.01, implied_event 1.08, scale 1.47, notes 0.23 |
| 단위(50장)당 소요 | 중앙값 약 9분 (기록상 520초) |
| 사용량 | 약 3,870만 토큰 (장당 약 3,320) |

- 요약 표는 `results/tables/`에 있다: `labeling_summary.md`(파일럿 300장), `six_dim_distribution.md`(6항목 값 분포), `dimension_expression_check.md`(개방/폐쇄 등 공간 표현이 기존 항목에 얼마나 나오는지), `coco_presence_covariates.md`(사람·동물 존재 비율).
- 코어 1,000장 이외의 이미지는 독립 샘플이 1번뿐이다.
- 항목별 최소 개수는 v10에서 9,800장 모두 충족했다. 코어 1,000장(v9)은 이 규칙이 생기기 전이라 867장(86.7%)이 미달이다(activity 80.1%, place_type 41.6%, environment 41.0%). 최소 개수 검사가 생기기 전에 통과시켰으므로 미달 표시도 없다. v10으로 다시 라벨링할지는 정하지 않았다.
- 이 검사는 날림 작업과 복사를 잡을 뿐, 라벨이 이미지 내용과 정말 맞는지는 알려 주지 못한다. 11,150장 중 일부를 직접 확인해서 보완할 예정이다(표본 크기와 기준은 확인 전에 정한다).

## 시행착오

| 시도 | 방식 | 문제 | 조치 |
|---|---|---|---|
| 파일럿 | 이미지 300장, Claude로 라벨링과 누수 판정 | 누수 표시가 65%(4항목)에서 84%(5항목)로 높고 표현이 흩어짐 | 누수를 삭제 기준이 아닌 표시로 두고, 항목 구조를 고침 |
| 1차 대규모 | 20장 배치 50개를 한 세션에서 이어서 처리 | 앞 이미지의 문장이 화장실 사진 49장에 그대로 복사됨 | 폐기 |
| 2차 | 복사 금지 규칙을 더해 다시 | 이미지를 보지 않고 끝냄. 작업이 캡션에서 라벨을 규칙으로 만드는 스크립트를 스스로 짜서 파일 50개를 1초에 생성, 다른 작업은 80장 이후 캡션을 정해진 틀에 끼워 넣음 | 폐기, 이미지 열람 기록을 검사에 추가 |
| 현재 | 단위별 새 세션 + 자동 검사 | 검증기가 이상한 값(문장 자리의 숫자)에 오류로 죽어 12시간 정지 | 이상한 값은 반려 처리, 오류가 나도 그 단위만 격리 |

## 데이터는 이 저장소에 없다

NSD 원본과 그 파생물(이미지 목록, 라벨, 로그)은 데이터 사용 계약(DUA) 때문에 저장소에 올리지 않는다(`.gitignore`가 `data/`를 막는다).
코드를 실행하려면 각자 DUA에 동의한 뒤 NSD와 COCO를 내려받아 `data/`를 채우고, Codex CLI 로그인이 필요하다.
